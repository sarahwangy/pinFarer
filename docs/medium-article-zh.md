# 我用 Claude + Mapbox 构建了一个 AI 旅行地图助手

我是一个喜欢记录旅行的人，但一直找不到一个工具能同时满足：在地图上标记去过的地方、管理想去的目的地、以及根据收藏的地点自动规划行程。

Pinfarer 就是为了解决这个问题而生的。

## 产品核心

**三种状态的 Pin 系统**

每个地点可以被标记为三种状态：
- **Visited**（已去过）— 有过真实体验的地方
- **Watchlist**（想去）— 具体有计划的目的地
- **Dream**（梦想清单）— 随手收藏、还没计划的地方

这三种状态对应了旅行者真实的心理阶段，而不是简单的"收藏/未收藏"。

## 技术栈

| 层级 | 技术 |
|------|------|
| 框架 | Next.js 14 (App Router) |
| 地图 | Mapbox GL JS（球形投影） |
| 数据库 | Supabase (PostgreSQL + JSONB) |
| AI | Anthropic Claude Sonnet 4.6 |
| 图片 | Pixabay API |
| 部署 | Vercel |

## 球形地图投影

最初考虑用标准的平面地图，但发现 Mapbox 支持 Globe Projection——真实的球形地球。

对于旅行主题来说，这个选择直接提升了产品的"感觉"。当你在地球上 Pin 一个地点，然后看着地球旋转飞向那个位置，这个交互本身就让人兴奋。

## AI 行程规划

这是最花时间但也最有价值的功能。用户可以：
1. 从已收藏的地点中选择目的地
2. 设置旅行天数（3–14天）、出行风格、偏好标签
3. Claude 生成按天拆解的行程，每个时间段有具体活动
4. 地图上同步显示路线和地点

Prompt 设计的关键是：让 Claude 知道用户已经收藏了哪些地点（说明用户真实有兴趣），再结合旅行偏好生成个性化行程，而不是通用的"Top 10 旅游景点"。

## KML 导入

很多用户在 Google Maps 里已经收藏了大量地点。我支持直接导入 Google Takeout 的 KML 文件，解析所有位置数据，用户预览后一键批量导入。

这个功能让 Pinfarer 不是从零开始，而是成为用户现有旅行数据的"新家"。

## 地点详情页

每个地点有两类数据：

**城市数据**：人口、语言、货币、气候、美食文化、签证信息、安全等级
**房产数据**（给考虑移居的用户）：学区、交通分数、CBD距离、中位房价

这些数据通过 Claude 实时生成，结合 Pixabay 图片作为视觉配图。

## 总结

Pinfarer 让我重新整理了散落在各处的旅行记忆——Google Maps 收藏夹、微信收藏、小红书点赞。把它们统一管理之后，发现自己其实已经"想去"很多地方了，只是之前这些愿望从来没有被好好整理过。

代码是工具，但背后是对旅行这件事的真实热爱。
